# ТЗ: Lecture Translate — минимальное macOS-приложение для перевода лекций

## 1. Цель

Разработать небольшое нативное macOS-приложение, которое слушает речь преподавателя через выбранный микрофон, транскрибирует английскую и китайскую речь и показывает перевод на русский в реальном времени.

Основной сценарий: лекция по китайскому языку, которую преподаватель объясняет на английском, периодически используя китайские слова, предложения и грамматические конструкции.

**Ключевое правило:** английские объяснения переводятся на русский, китайские слова и предложения сохраняются иероглифами, без обязательного перевода.

Например:

Input:
"The construction 因为…所以… is used to express cause and effect."

Output:
"Конструкция 因为…所以… используется для выражения причины и следствия."

Конспектирование, AI-ассистент, генерация учебных материалов и другие функции в MVP не нужны.

## 2. Интерфейс

Нативное компактное приложение на SwiftUI.

Требования:

- Одно небольшое окно macOS.
- Выбор микрофона из доступных аудиоустройств.
- Кнопка Start — начать запись и распознавание.
- Кнопка Stop — остановить запись и распознавание.
- Кнопка Save — сохранить исходное аудио и транскрипцию.
- Отображение русского перевода во время записи.
- Возможность прокручивать предыдущий текст.
- Минимальный индикатор состояния: Idle / Recording / Processing / Error.

Интерфейс должен оставаться небольшим и не отвлекать пользователя. Предусмотреть удобное изменение размера окна.

Не добавлять в MVP навигацию по разделам, аналитику, дашборды или сложную систему настроек.

## 3. Технологии

- Платформа: macOS.
- Интерфейс: SwiftUI.
- Захват микрофона: AVFoundation / Core Audio.
- Аудио: обработка через AVAudioEngine.
- Speech-to-Text: адаптер OpenRouter с поддержкой замены ASR-модели.
- Перевод: текстовая LLM через OpenRouter.
- Хранение: локальная файловая система.
- Авторизация API: OpenRouter API key, хранить через macOS Keychain.

Не использовать Soniox, Deepgram или другие платные API вне OpenRouter.

### ASR

Первый кандидат — Qwen3-ASR-1.7B через OpenRouter, при условии актуальной доступности модели на endpoint транскрипции.

Предусмотреть альтернативные модели, например Whisper или Voxtral, если они поддерживают нужный endpoint.

Официальный endpoint:

`POST https://openrouter.ai/api/v1/audio/transcriptions`

Поскольку этот endpoint работает с аудиофрагментами, разработать псевдопотоковую обработку коротких сегментов.

Для локального ASR в дальнейшем предусмотреть возможность отдельного адаптера, но не делать локальный инференс обязательным для MVP.

### Перевод

После распознавания отправлять стабилизированный текст в быструю текстовую LLM через OpenRouter.

Правила:

- Переводить английский на естественный русский.
- Не изменять китайские иероглифы.
- Сохранять порядок объяснений.
- Не добавлять комментарии и пояснения от модели.
- Не придумывать пропущенные слова.
- Учитывать небольшой контекст предыдущих реплик.
- По возможности сохранять имена, учебные термины и грамматические обозначения.

Не запускать тяжёлое агентное рассуждение. Предпочитать малую задержку.

## 4. Поток обработки

1. Пользователь выбирает микрофон.
2. Нажимает Start.
3. Приложение начинает записывать оригинальное аудио в локальный файл.
4. Параллельно аудио поступает в буфер распознавания.
5. VAD определяет речевые участки и паузы.
6. Приложение отправляет короткие аудиосегменты в OpenRouter.
7. Полученная транскрипция передаётся в LLM для перевода.
8. Русский перевод отображается в окне.
9. Пользователь нажимает Stop.
10. Приложение завершает обработку оставшихся сегментов.
11. Пользователь нажимает Save и выбирает место сохранения.

Запись оригинального аудио должна быть независима от запросов к API. Ошибка OpenRouter не должна приводить к потере исходной записи.

## 5. Работа в реальном времени

Для MVP:

- Начальный размер аудиосегмента: 3 секунды.
- Использовать VAD для определения естественных границ фраз.
- Допускать небольшое перекрытие сегментов.
- Обрабатывать запросы асинхронно.
- Не допускать дублирования текста при перекрытии фрагментов.
- Сохранять правильный порядок реплик даже при разном времени ответа API.
- Не блокировать пользовательский интерфейс во время обработки.

Целевой показатель — задержка перевода примерно 3–5 секунд после произнесённой фразы, если позволяет производительность API.

Это инженерная цель, а не гарантированная характеристика OpenRouter. Реальную задержку необходимо измерить.

Если ответы API приходят медленнее поступления аудио, приложение должно показывать состояние отставания обработки и не терять запись.

## 6. Сохранение

При нажатии Save пользователь выбирает папку.

Создаётся папка с именем сессии и датой, содержащая:

- `recording.m4a` — исходная запись лекции.
- `transcript.txt` — оригинальная распознанная речь.
- `translation.txt` — русский перевод с сохранением китайских вставок.
- `session.json` — структурированные сегменты, временные метки, модель, статусы и технические данные.

Для каждого сегмента в JSON сохранять:

- ID и порядковый номер.
- Время начала и конца соответствующего аудиофрагмента.
- Исходную транскрипцию.
- Русский перевод.
- Использованные модели.
- Статус обработки и ошибки.

Временные метки сегмента не выдавать за точные таймкоды отдельных слов.

## 7. Обработка ошибок

Обязательно:

- Понятное сообщение при отсутствии доступа к микрофону.
- Реакция на отключение выбранного устройства.
- Обработка ошибки, таймаута или лимита OpenRouter.
- Возможность повторно обработать неудачный сегмент.
- Отмена или контролируемое завершение незаконченных запросов при Stop.
- Защита от потери аудиофайла при сбое приложения.
- Отсутствие дублированных и перепутанных сегментов.

При отсутствии интернет-соединения продолжать локальную запись, сохраняя необработанные фрагменты для последующей обработки.

## 8. Ограничения MVP

Не реализовывать:

- Авторизацию пользователей.
- Облачное хранение.
- Синхронизацию между устройствами.
- Генерацию конспектов.
- Историю сессий внутри интерфейса.
- Систему подписок.
- Многооконный интерфейс.
- Распознавание отдельных говорящих.
- Сложные настройки моделей в UI.

Настройки моделей и технические параметры допустимо вынести в конфигурационный файл.

## 9. Критерии готовности

MVP принимается, если:

1. Приложение запускается на Mac и показывает доступные микрофоны.
2. Start запускает непрерывную запись.
3. Оригинальная запись сохраняется даже при ошибках API.
4. Распознаются английские объяснения и китайские вставки.
5. Английский переводится на русский, а китайские иероглифы не теряются при корректной ASR-транскрипции.
6. Перевод постепенно появляется в интерфейсе.
7. Stop корректно завершает запись и обработку.
8. Save сохраняет аудио, исходную транскрипцию, перевод и JSON.
9. Приложение выдерживает непрерывную 60–90-минутную сессию без потери аудио.
10. Реальные задержки, ошибки распознавания и стоимость запросов измерены и задокументированы.

## 10. Порядок реализации

**Этап 1:** исследовать доступные модели OpenRouter и проверить фактическую работоспособность ASR на английско-китайском аудио.

**Этап 2:** реализовать нативное окно SwiftUI и захват выбранного микрофона.

**Этап 3:** добавить запись аудио и отправку сегментов в OpenRouter.

**Этап 4:** подключить LLM-перевод и отображение текста.

**Этап 5:** реализовать Stop, Save и экспорт файлов.

**Этап 6:** протестировать на реальном аудио лекции и устранить дубли, пропуски, задержки и ошибки переключения языков.

Принцип реализации: максимально простое приложение с небольшим числом компонентов, чистыми интерфейсами между захватом аудио, ASR, переводом и хранением. Не усложнять архитектуру без необходимости.
