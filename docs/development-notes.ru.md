# Архив инженерных заметок Voxtant

История реализации и экспериментов. Актуальная пользовательская инструкция — [README.ru.md](../README.ru.md). Команды выполняются из корня репозитория.

# Voxtant

*Your live interpreter.*

Voxtant — персональный синхронный переводчик для macOS. Он слушает живую речь
через микрофон и постепенно показывает перевод. Продукт задуман для разговоров,
встреч, лекций и выступлений; языки распознавания и перевода настраиваются.

Текущая демка проверяет путь **микрофон → OpenRouter ASR → перевод по языковым правилам**.
Первый реализованный сценарий — английские объяснения с китайскими вставками:
английский переводится, а распознанные китайские иероглифы сохраняются.
Аудио обрабатывается короткими фрагментами: непрерывного потокового ASR пока нет.

**Статус на 2026-11-02:** пользователь подтвердил, что улучшенная демка работает
достаточно хорошо, чтобы продолжать проект. Базовая техническая осуществимость
подтверждена короткими живыми прогонами. Это не приёмка полного MVP: точность
китайского, длинная сессия и устойчивость API остаются открытыми.

## Запуск

Нужны macOS 14+, установленный Xcode / Swift 6 и ключ OpenRouter с балансом.
Внешних зависимостей, серверов и dev-stack нет.

```sh
make dev
```

Запускается `dist/Voxtant.app` — приложение с иконкой волны в строке меню macOS,
без основного окна и иконки в Dock. Нажмите на волну, чтобы открыть виджет.
Перетащите его за верхнюю полоску или название: положение сохраняется, клик
в другом приложении его не скрывает. Повторный клик на волну скрывает панель; следующий возвращает её
на прежнем месте. Скрытие не останавливает запись. Правый клик по иконке открывает команды скрытия, настроек и выхода.

Через шестерёнку откройте настройки, введите ключ и нажмите «Сохранить».
Ключ остаётся в macOS Keychain. Не кладите его в код, файлы конфигурации или чат.
При первой записи разрешите доступ к микрофону в диалоге macOS.

На macOS 26+ используется системный SwiftUI Liquid Glass; на macOS 14–15 —
нативный полупрозрачный материал AppKit. Виджет по умолчанию имеет размер 340 × 420 pt; его можно растягивать за края или нижний правый угол (от 300 × 300 pt). Размер и положение сохраняются. При этом виджет
держится поверх обычных окон и настроен для Spaces/full-screen. При отключении
монитора положение ограничивается границами доступного экрана.

1. Выберите микрофон через левую нижнюю кнопку и нажмите круглую кнопку записи справа.
2. Читайте перевод в виджете; последние строки выделяются, предыдущие можно прокрутить.
3. Кнопка Stop останавливает микрофон, отменяет запросы и очищает очередь без ожидания API. Готовый текст и исходное аудио сохраняются.
4. Настройки → «Модели»: выбор распознавания и модель перевода. Выбор сохраняется между запусками.
   «Дополнительно»: свой ID ASR-модели, отмена запросов, повтор ошибок и порог речи.
5. Там же «Экспорт…» копирует сессию, а «Папка сессии» открывает рабочие файлы.

Для повторяемого сравнения моделей в настройках → «Дополнительно» можно выбрать «Аудиофайл…».
Это пакетная обработка, а не измерение задержки живого микрофона.
При низком уровне речи настройте порог в настройках → «Дополнительно»: более отрицательное значение
чувствительнее к тихой речи и фоновому шуму. Значение по умолчанию −48 dBFS.

## Языки перевода

Настройки → «Перевод»:

- **Обычный:** фиксированные язык записи и язык перевода. Например, китайский → русский,
  включая перевод китайской речи, без сохранения иероглифов по умолчанию.
- **Смешанный:** общий язык перевода и список языков записи. Галочка «Переводить»
  переводит этот язык; без галочки услышанное остаётся на исходном языке.
  Можно добавлять и убирать языки, оставляя хотя бы один.

По умолчанию выбран смешанный режим: английский переводится на русский,
китайский сохраняется. Например, `The pattern 因为…所以… expresses cause and effect.`
должен стать `Конструкция 因为…所以… выражает причину и следствие.`
В виджете показывается один итоговый текст без второго блока исходной транскрипции.
Оригинальная расшифровка по-прежнему сохраняется в `transcript.txt`.

Доступен выбор английского, китайского, русского, немецкого, французского,
испанского, итальянского, португальского, японского и корейского. Этот список —
конфигурация запросов, а не подтверждение одинаковой точности ASR для всех языков.
Настройки сохраняются между запусками и фиксируются на старте сессии; менять их
можно сразу после Stop или завершения обработки файла. Повтор ошибок использует правила исходной сессии.
В новых `session.json` правила находятся в необязательном поле `translationSettings`;
существующие отчёты schema v2 читаются без него.

Обычный режим передаёт выбранный ISO-код языка в STT, смешанный оставляет автоопределение
([контракт OpenRouter](https://openrouter.ai/docs/guides/overview/multimodal/stt)).
Gemini ASR получает подсказку о выбранных языках и нативной письменности.
Qwen STT не получает такую текстовую подсказку: качество переключений зависит от модели.
Китайские вставки защищаются кодом, если китайский оставлен в оригинале и среди
исходных языков нет японского: Han-символы общие для двух письменностей.
При совместном китайском/японском и для остальных сохраняемых языков правило
выполняет модель; отдельной посимвольной проверки этих языков пока нет.

## Основной пул распознавания

В настройках → «Модели» доступны Scribe v2 и GPT Transcribe.
Выбор распознавания и ID переводчика сохраняются после перезапуска. Они зафиксированы
для дальнейшего сравнения качества смешанной речи; подтверждённого победителя пока нет.
Решение и ограничения — [docs/asr-selection.md](../docs/asr-selection.md).
Эксперимент с предварительной строкой за 3 секунды и уточнением по 6 секундам:
`make eval-context DATASET=…` (отдельные платные запросы).

## Проверка гипотезы

Модели по умолчанию:

- ASR: `elevenlabs/scribe-v2` (новый default; сохранённый выбор модели остаётся);
- перевод: `openai/gpt-4.1-mini` (выбран после сравнения шести моделей).

Модель распознавания и модель перевода можно изменить перед следующей сессией в настройках → «Модели».
Свой OpenRouter ID распознавания можно ввести в «Дополнительно».
В смешанном режиме доступен «Приоритетный язык» для распознавания. Если короткие
китайские вставки превращаются в пиньинь/кириллицу, попробуйте «Китайский».
Эта подсказка не меняет язык перевода и галочки сохранения исходных языков;
по умолчанию остаётся «Автоматически». Сохранение иероглифов не гарантирует
правильность распознанных слов. В обычном режиме приоритет имеет язык записи.
У Scribe отключены звуковые события: `[outro jingle]` не должны становиться
переведённой подписью к фоновому звуку. [Проверка параметров](../docs/scribe-language-options.md).

Основной ASR-пул — Scribe v2 и GPT Transcribe. Qwen ASR исключён из приложения
и дальнейших тестовых запросов; его сохранённый выбор заменяется на Scribe. Старые отчёты остаются историей.
Для сравнения переводчиков можно указать `qwen/qwen3-next-80b-a3b-instruct`: он быстрее
на наших коротких примерах, но уступил GPT-4.1 mini в термине «счётное слово».
Сохранённый старый переводчик Flash Lite автоматически заменяется выбранным default;
другие пользовательские ID сохраняются. [Результаты сравнения](../docs/translation-selection.md).
Все запросы идут через `https://openrouter.ai/api/v1/`.
Qwen ASR использует `audio/transcriptions`, перевод — `chat/completions`.
В смешанном режиме язык ASR не фиксируется как английский: это помешало бы переключению языков.

Начните с 2–3 минут речи: обычные объяснения, быстрые предложения, паузы,
отдельные китайские слова и повторы одного примера. Затем попробуйте 10–15 минут.
Сравнивайте оригинальную запись, ASR и перевод: переводчик не может восстановить
иероглифы, потерянные на этапе ASR.

Перевод появляется постепенно через SSE: предварительная строка приглушена,
после завершения ответа и проверок становится окончательной. Защищённые китайские
вставки восстанавливаются только целиком; служебные токены не показываются.
Предварительный текст может измениться и не попадает в экспорт.

Виджет показывает текст, состояние записи и стоимость. Технические метрики
сохраняются в `session.json`: ASR, перевод, очередь попыток и задержка **от конца
аудиофрагмента до готового перевода**. К этому добавляется ожидание границы фрагмента
во время произнесения фразы: это не обещание задержки от каждого слова.
Стоимость сохраняется только при наличии данных API; отсутствующая стоимость неизвестна.
Отсутствующая стоимость не означает бесплатный запрос. Повторные запросы оплачиваются отдельно.

## Стоимость

Снизу виджета мелко показана сообщённая OpenRouter сумма в USD и приблизительный
эквивалент в рублях. Курс ЦБ загружается в фоне, кэшируется на 6 часов и фиксируется
для сессии; дата и источник доступны при наведении. При недоступном курсе остаются
доллары. Это официальный ежедневный курс, а не курс списания банка.
«От» означает известную часть стоимости: отменённые/неоценённые запросы не
считаются бесплатными. Ключ и приватный звук в сервис курса не отправляются.

## Сохранение

Новые сессии автоматически сохраняются на рабочем столе:

```text
~/Desktop/Voxtant Recordings/
  2026-11-03/
    14-30-00_A1B2C3D4/
      recording.caf
      transcript.txt
      translation.txt
      metadata.json
      session.json
      chunks/
```

Дневная папка создаётся при первой записи в этот день; каждая запись получает
отдельную папку времени/ID. Старые записи в прежней служебной папке не переносятся.
`metadata.json` содержит модели, языки, микрофон, параметры аудио, длительность,
состояние и стоимость. `session.json` сохраняет подробный совместимый формат v2.

- `recording.caf` — непрерывная исходная запись, независимо от API;
- `chunks/*.wav` — фрагменты mono 16 kHz PCM16, включая неудачные;
- `transcript.txt` — распознанный оригинал;
- `translation.txt` — готовый перевод;
- `session.json` — порядок, границы, модели, статусы, ошибки, задержки и доступная стоимость.

Для импорта вместо `recording.caf` сохраняется копия выбранного исходного файла.
JSON и тексты обновляются атомарно по мере обработки. После сбоя файлы остаются
на диске; автоматического восстановления очереди в интерфейсе в этой демке нет.
Отменённые через Stop фрагменты отмечаются `translationMode=cancelled-by-user`,
без ошибок отмены в виджете. Они не дорабатываются автоматически и не считаются
готовыми переводами. Их WAV и уже распознанный оригинал сохраняются.
Ключ в экспорт не попадает. Экспорт и открытие папки находятся в настройках → «Дополнительно».
Для совместимости с первой демкой сохранены технический bundle ID
`local.lecturetranslate.demo`, сервис Keychain и прежнее имя папки сессий.
Новая библиотека на рабочем столе не меняет старые записи. Переименование приложения не требует переноса записей или повторного ввода ключа
при сохранённом доступе macOS Keychain.
В схеме JSON v2 сохраняются время очереди, старта ASR, готовности оригинала,
старта перевода, показа результата и журнал каждой попытки HTTP с кодом,
длительностью, ID запроса, провайдером и `Retry-After`, когда они доступны.

## Диагностика микрофона

Перед стартом выбранный микрофон повторно находится по устойчивому UID:
числовой CoreAudio ID может измениться после подключения устройства или
перестройки аудиографа. Отключённый микрофон не заменяется другим автоматически.

`make audio-smoke AUDIO_SMOKE_DIR=/new/private/directory` выполняет два локальных
односекундных запуска микрофона и проверяет записанные кадры. Требуется уже
выданный доступ к микрофону; проверка не запрашивает ключ и ничего не отправляет
в API. CAF и `result.json` остаются в новой указанной папке вне репозитория.
Эта аппаратная проверка не входит в `make verify`.

## Границы демки

- Фрагменты обычно 1.2–2.8 секунды, завершаются на паузе или на предельной длине.
  Перед началом речи оставляется 120 мс звука; длительная тишина в API не уходит.
- Копии WAV для ASR нормализуются до пика 0.8 с усилением не выше 8×.
  Это не удаление шума. Исходная непрерывная запись не изменяется.
- Энергетический детектор нарезает аудио; перед ASR работает дополнительный локальный
  фильтр Apple SoundAnalysis. Фрагмент от 1 секунды с очень низкой оценкой речи во всех
  окнах не отправляется в API. Короткие, сомнительные и неудачно проверенные фрагменты
  проходят в ASR. Фильтр не исправляет неверно услышанные слова.
  Исходный CAF и все WAV остаются сохранены; решение фильтра записывается в заметки JSON.
  Подробнее: [проверка фильтра речи](../docs/speech-gate.md).
- Без перекрытия и текстового удаления дублей: сохраняются намеренные повторы.
  На принудительной границе возможны разрезанные слова — это предмет проверки ASR.
- До двух ASR-запросов и двух переводов параллельно; ячейки и экспорт остаются
  в порядке аудио. Один неудачный запрос больше не блокирует перевод следующих ячеек.
  Контекст — до трёх доступных предыдущих реплик, без последующих.
- Свежий микрофонный фрагмент ASR получает одну попытку до 8 секунд. При временном
  сетевом сбое без `Retry-After` WAV остаётся в очереди восстановления: до двух
  дополнительных попыток по 8 секунд в бюджете 20 секунд. Свежий звук имеет приоритет;
  во время записи восстановление занимает не более одного из двух ASR-слотов.
  Stop отменяет и очередь восстановления, и активные запросы. Поздние ответы
  игнорируются; новая запись доступна после локального сохранения хвоста аудио.
  Для файлов и перевода — до 3 попыток по 8 секунд в бюджете до 20 секунд.
  HTTP 408/429/500/502/503/504 и некоторые сетевые сбои повторяются с паузой.
  `Retry-After` соблюдается: если пауза не укладывается в live-бюджет,
  сегмент остаётся ошибочным для ручного повтора. Ошибки ключа/баланса не повторяются.
- При включённом сохранении китайского (без японского в исходных языках) полностью
  китайская реплика проходит без переводчика, с точным сохранением ASR-текста.
  В смешанной реплике китайские фрагменты заменяются защищёнными токенами и
  восстанавливаются кодом. Проверяются потери, повторы, порядок и добавленные
  иероглифы (кроме перевода на китайский/японский); при нарушении — один повтор валидации. Это защищает ASR-текст,
  но не исправляет ошибки самого ASR и не доказывает смысловую точность перевода.
- При ошибках сети запись продолжается; ошибки можно повторить после Stop.
- Исходник сохраняется в CAF, а не M4A: для демки выбран простой несжатый формат.
  При 48 kHz Float32 это около 0.7 GB/час на канал. Проверяйте свободное место.
- 60–90-минутная устойчивость, качество на настоящей лекции, реальная стоимость
  и целевая задержка 3–5 секунд требуют живого прогона. Сборка и unit-тесты этого не доказывают.
- Подпись приложения локальная (ad hoc), распространение и notarization не настроены.

## Разработка

```sh
make build                    # Собрать .app
make test                     # Локальные тесты, без API и микрофона
make test-one FILTER=CoreTests/testChineseGuardChecksOrderAndRepetitions
make lint                     # Проверить plist и shell syntax
make typecheck                # Swift build
make verify                   # Тесты, проверки, сборка .app
make ui-smoke                 # UI-проверки собственных окон, без аудио/API
```

`Sources/LectureCore` содержит сегментацию, WAV, API и структуры отчёта.
`Sources/LectureTranslate` — SwiftUI, Keychain, захват и оркестрацию.
`MenuBarController.swift` управляет иконкой, перемещаемой панелью и настройками;
`WidgetView.swift` и `SettingsView.swift` разделяют два интерфейса.
`make ui-smoke` требует живую macOS GUI-сессию. На macOS 14.4+ снимает только окна
текущего тестового процесса через `SCShareableContent.currentProcess`, без доступа
к чужим окнам, микрофону, Keychain или API. Снимки и отчёт — `.build/ui-smoke/`.
Декларации Spaces проверяются по конфигурации; реальная смена Spaces вручную не автоматизирована.
Тесты проверяют границы аудио, хвост Stop, тишину, WAV, сохранение иероглифов,
формат ASR-запроса, повтор повреждённого перевода и HTTP 429 на HTTP-заглушке.
Дополнительно проверяются выбранный язык ASR, оба режима перевода, галочка китайского,
цель с Han-символами, сохранение настроек и совместимость отчётов без языковых правил.

Источники контракта API: [OpenRouter Speech-to-Text](https://openrouter.ai/docs/guides/overview/multimodal/stt),
[Qwen3 ASR 1.7B](https://openrouter.ai/qwen/qwen3-asr-1.7b),
[Audio input](https://openrouter.ai/docs/guides/overview/multimodal/audio),
[Errors / Retry-After](https://openrouter.ai/docs/api/reference/errors-and-debugging).

## Валидационный датасет

Для повторяемой проверки записей iPhone есть отдельный CLI `VoxtantEval` и
Python-инструменты без внешних Python-зависимостей. Они фиксируют аудиофрагменты,
разделяют записи по дням на рабочую и отложенную части, сохраняют конфигурацию,
хеши кода/аудио, контексты, попытки API и историю оценок. Прогоны используют
тот же `LectureCore`, что и приложение. Локальные тесты метрик входят в `make verify`;
платные API-прогоны запускаются отдельно.

Порядок подготовки, разметки, прогона и сравнения — [docs/validation.md](../docs/validation.md).
По умолчанию доступна автоматическая проверка `make eval-auto DATASET=…`: Whisper,
Scribe и GPT Audio создают отдельные машинные ориентиры, спорные примеры остаются
в карантине. Отчёт показывает расстояния до этих ориентиров и покрытие.
Расширенный ASR-пул без Gemini запускается отдельно: `make eval-candidates DATASET=…`.
По умолчанию он сравнивает три основные модели; `--expanded` возвращает семь моделей на цельных отрывках и одинаковых коротких фрагментах;
прямые потоковые API проверяются отдельным этапом.
Человеческая разметка необязательна; подтверждённая абсолютная точность
MER/WER/CER и машинные proxy-метрики разделены. Аудио, разметка и расшифровки остаются вне Git.

На одном смешанном фрагменте Qwen выдал `For example, washy, laushy, nishy.`,

скрипт по умолчанию выбирает последнюю сессию.

## Контроль регрессий качества

Независимый набор из 14 заранее заданных синтетических сценариев проверяет
нативную нарезку и ASR: отрицания, числа, иероглифы, повторы, тишину и шум.
`quality-freeze` сохраняет неизменяемую исходную оценку, `quality-compare` показывает
изменения на тех же аудиофайлах, `quality-status` проверяет актуальность по коду.
Платный `quality-run` запускается явно; в `verify` входят только локальные тесты.
Результат — согласие с синтетическим сценарием, а не точность на живой лекции.
Команды и ограничения: [docs/quality-regression.md](../docs/quality-regression.md).
